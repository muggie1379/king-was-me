# 통합 우선순위 제안 — Claude (2026-09-19)

사용자 지시: "분석 결과를 프로젝트 안에 파일로 먼저 저장하고, 작업 우선순위를 능동적으로 정해서 다시 물어봐 달라."
입력: 제 스토리 더블체크(`reviews/story-midpoint-audit_claude_double-check_20260919.md`), 제 Unity 기술 점검(`verification/unity-technical-midpoint-audit_claude_report.md`), 코덱스 두 보고서(스토리 감사, 통합 감사), 사용자 방향(MVP 복제 아님, Unity 고유 연출, 대신 4명 초과 확장, 회의 좌석 연출, 디자인 작업은 Codex).

## 권장 순서

**0단계 — 결정 2건 (구현 전에 사용자 확인)**
- 대신 UI 방향: 데이터 기반 명단 + 좌석 뷰/의견 카드 두 층 분리를 채택할지.
- 사건 재생 구조: 단계 러너 + 프레젠터(Timeline/Animator) 방식을 채택할지.

**1단계 — 기반 (Claude, 새 콘텐츠 작성 전)**
1. 사건 단계 러너 + 콘텐츠 데이터 형식(Ink 태그) 확정.
2. 하드닝: 입력 잠금·오류 표면화·`AssetCatalog`(빌드 가능 경로)·제목 화면 결함·배경 종횡비·키보드·Enter Play Mode Options.
3. 대신 명단 데이터화(`AdvisorProfile`/`CourtRoster`) + 4칸 고정 카드 제거.

**2단계 — 수직 슬라이스 (Claude 구현 + Codex 디자인 자료 병행)**
4. Event 1~2: 의견 종합 → 짧은 논쟁 → 왕의 정적(좌석 시선 연출) → 선택 → aftermath → 결과가 붙은 왕실 기록.
5. 개발용 상태 패널(선택 이력, 국가 값, 활성 분기, 죽은 변수 정리).
6. 두 번째 게이트: 타이머/침묵이 있는 사건(E13) 1개로 러너 재사용 검증.

**3단계 — 콘텐츠·후반 (Codex 중심, Claude 검증)**
7. Ink에서 설계 메모 5곳 교체, E24/E25 결말을 E23 선택과 연결, 엔딩 태그화.
8. 엔딩 디렉터(KING WAS YOU → 휴대폰 → 빈 왕좌 → 1인칭 → 최종 대사) 구현.

**병행(Codex)**: 디자인 자료(좌석 포즈, 회의장, UI 키트), `ASSET_MANIFEST.md` 갱신, 에셋 폴더 규칙, 무료 자료 라이브러리 계획.
**미룸**: 저장/불러오기, 2회차, 스탠드얼론 빌드 패키징(단, 카탈로그 전환은 1단계에 포함), Addressables.

## 근거 요약
- 코덱스 P0와 제 P0가 같은 뿌리를 가리킨다: 사건을 단계로 재생하는 구조와 그 구조가 재생할 콘텐츠 데이터가 없다. 이걸 두고 HUD·에셋만 더하면 재작업이 커진다.
- 기획서 v1.0 §29의 "Event 1~2 수직 슬라이스" 게이트와 일치한다.
- 사용자 방향(Unity 고유 연출)은 러너/프레젠터 분리로 자연스럽게 수용된다. 프로젝트에 Timeline과 2D Animation이 이미 있다.

## 리스크
- 검증 환경(에디터 브리지)이 리로드마다 끊기는 문제가 개발 속도를 깎는다(기술 점검 P0-2).
- 대신 자료(포즈 세트)의 일관성은 이미지 생성 도구 한계에 달려 있어 Codex의 가능 여부 답이 필요하다.
- 콘텐츠 밀도(대신 해석·aftermath)는 신규 집필 범위라 사용자 승인이 필요하다.
