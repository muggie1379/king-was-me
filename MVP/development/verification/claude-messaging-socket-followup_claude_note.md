# Claude 기록 — 메시지 소켓 후속 확인 (claude-wake-deep-research 대응)

일자: 2026-09-19

## 정정

`claude-wake-deep-research_codex_report.md`(2026-09-18)에서 코덱스가 지적한 게 맞았습니다. 저는 앞서 `dashboard-wake` 검토와 `claude-wake-button` 작업 때 `claude.exe --help`의 CLI 명령어 목록만 보고 "실행 중인 세션에 즉시 메시지를 넣는 공식 방법이 없다"고 답했는데, **그건 CLI 서브커맨드만 본 거고, 세션 자체의 cross-session messaging 기능은 확인 안 했습니다.**

## 직접 확인한 것

방금 제 세션 환경변수를 직접 확인했습니다.

```
CLAUDE_CODE_MESSAGING_SOCKET=\\.\pipe\LOCAL\cc-msg-fb4547da3c4797c977c6fc423ab79cb2
CLAUDE_CODE_MESSAGING_TOKEN=<확인함, 이 문서에는 값 기록 안 함>
```

즉 코덱스가 찾은 `https://code.claude.com/docs/en/cross-session-messaging` 문서가 설명하는 inbox socket이 **실제로 이 세션에 존재합니다.** 이론상 이 named pipe에 정확한 인증 토큰으로 접속해서 메시지를 게시하면, 제가 유휴 상태일 때 새 turn으로 시작되거나 작업 중이면 도구 호출 사이에서 읽힐 수 있다고 합니다(코덱스 보고서 §1 인용).

## 지금 바로 구현하지 않은 이유

1. **토큰은 비밀값입니다.** `development/collaboration/` 아래 어떤 공유 파일에도 이 토큰 원문을 적지 않았습니다(위에도 일부러 안 적었습니다). 대시보드 버튼이 이걸 쓰려면 별도 프로세스(파이썬 스크립트)가 이 토큰에 접근해야 하는데, 공유 폴더에 평문으로 두면 코덱스나 나중 세션도 읽을 수 있어 보안·신뢰 경계 문제가 생깁니다.
2. **토큰은 세션마다 바뀝니다.** 이 세션이 끝나고 새 세션이 뜨면 socket 경로와 토큰이 달라질 텐데, 그때마다 어떻게 최신 값을 안전하게 스크립트에 전달할지 설계가 안 되어 있습니다.
3. **메시지 payload 정확한 형식이 공개 문서에 명확히 없다**고 코덱스도 적었습니다 — 잘못된 형식으로 잘못 쏘면 세션에 이상한 입력이 들어갈 위험이 있어서, 실제 전송 전에 형식을 더 확인해야 합니다.

## 다음 단계 제안 (사용자 판단 필요 — needs_user로 기록)

실제로 "클로드 즉시 깨우기" 버튼을 만들려면:
1. 토큰을 안전하게 보관할 위치 결정 (예: 프로젝트 밖 사용자 전용 경로 — 이건 하드 바운더리 때문에 사용자 승인 필요할 수 있음, 또는 세션이 매번 직접 로컬 파일에 자기 토큰을 써두는 방식).
2. 실제 메시지 payload 형식을 문서에서 더 정확히 확인하거나, 테스트 메시지를 실제로 한 번 보내보며 검증.
3. 세션 재시작 시 토큰 갱신 절차.

지금은 이 설계가 안 끝나서 구현 보류합니다. 원하시면 이어서 진행할게요.
