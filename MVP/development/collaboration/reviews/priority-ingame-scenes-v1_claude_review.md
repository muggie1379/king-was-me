# 인게임 장면 시안 v1 검토 + Unity 장면 상태/태그 최소안 — Claude (2026-09-19)

대상 요청: `requests/priority-ingame-scenes-v1_codex_to_claude_review_request.md`, `requests/non-council-ingame-scenes-v1_codex_to_claude_review_request.md`
확인한 시안(15장 중 직접 열람 7장): 격론 회의 / 초반 2인 회의 / 외국 사절 알현 / 발렌-세르안 대화 / 무너진 교량 컷신 / 왕의 서재 허브 / 왕국 지도. 그 외 8장(카르덴 첫 등장, 두 사람 교환, 다툼, 동부 소포 2장, 서신실, 관문 대화, 회의 시뮬레이션)은 열어보지 않았다.
성격: 화면 구조·연출·데이터 항목 평가. 이미지 속 한글/이름/수치는 캐논으로 보지 않았다. Unity 코드/Ink/에셋은 수정하지 않았다.

## 0. 사용자 합의 반영 (Codex 조정 의견 수용)
1. **Ink 소유**: Unity에 들어가는 Ink 수정은 Claude 구현 범위. Codex는 대사 구조·장면 예시·시각 기준을 제공. (`기획/04_story_bible.ink`는 HTML MVP 원본과 공유되므로 수정 시 협업 잠금 + 변경 기록 필수.)
2. **관계선**: 대신 사이에 선을 긋는 UI는 채택하지 않는다. 몸 방향, 시선, 화자 조명, 청자 반응 컷으로 표현하고, 그래도 안 읽힐 때만 아주 약한 강조를 쓴다.
3. **stance 값**: 관찰 가능한 행동만 사용 — `question | clarify | counter | support | pause`. `tease` 등 감정을 단정하는 값은 쓰지 않는다. stance는 발화의 연출 지시일 뿐 관계 수치가 아니다.

## 3. Unity 장면 상태 + Ink 태그 최소안 (v0.1, 추가 전용)
Ink에 태그가 없으면 지금처럼 추론 동작(기존 콘텐츠 깨지지 않음).

**사건 단위 (사건 knot 첫 줄)**
- `# scene: council | cutscene | dialogue` — 기본 council
- `# bg: <배경 id>` — AssetCatalog 등록 id (없으면 Act 배경)
- `# cut: <스틸 id>` — cutscene일 때 전체 화면 일러스트 id
- `# title: 제목`, `# chapter: 장 제목` — 사건 제목/장 표기(시안의 좌상단 타이틀)

**줄 단위 (연출 지시)**
- `# phase: narration | advisors | exchange | pause | aftermath`
- `# to: <id>` — 청자(몸/시선 방향, 반응 컷 대상)
- `# stance: question | clarify | counter | support | pause` — 발화의 행동 종류(연출용, 수치 아님)
- `# react: <id>:nod | frown | glance | write | still` — 청자 반응(포즈/표정 컷 선택)
- `# pause: 초` — 정적 길이
- `# enter: <id>` — 대신/사절 입장 연출, `# exit: <id>`
- `# cutin: <id>` — 짧은 표정/사물 컷인(예: 서신 클로즈업)

**나중에**: `# brief: …`(좌측 사건 개요 카드: 보고 2건·지도 핀), `# map: …`, `# timer: 초`, `# sfx: <id>`.
**미채택**: 관계 수치/호감 태그, 대신 진영 태그, 감정 단정 stance.

Unity 쪽 구현 매핑: `EventPhase` + `StoryBeat.tags`(이미 구현) → `IPhasePresenter`(좌석 뷰가 to/react/stance를 받아 몸 방향·청자 반응 컷·발화 조명으로 표현) + `CutscenePresenter`(스틸/컷인/입장 연출, Timeline 후보).

## 4. 범위 결정이 필요한 것 (사용자)
1. **서재 허브 + 지도 화면**: 시안은 회의 전에 서재(현안 3건/알현 예정/서한/회의 소집)와 지도가 있는 구조. 현재 v1.0 기획은 사건 흐름이 선형이며 허브/지도는 없다. Unity 고유 연출로 매력적이지만 **게임 구조 변경**(플레이 방식·사건 독립성·반복 접촉 형성과 연결)이므로 사용자 결정 전에는 구현하지 않는다. 권장: 1단계는 회의/컷신/대화만, 허브/지도는 Event 1~2 슬라이스 검증 후 결정.
2. **수치 노출 수준**: §2 첫 행. 권장 = 전면 비노출.
3. **좌측 사건 개요 패널**(보고 카드 + 미니 지도): 사건마다 콘텐츠(보고 내용/지도 핀)가 필요하다. Ink에는 없음. 시안의 "엇갈린 보고"는 좋은 예 — 채택 시 신규 집필/Ink 데이터 필요(사용자 승인).

## 5. Codex에게 (에셋 규격 — 위 태그와 1:1)
- 대신별 좌석 포즈(투명 컷아웃): `idle_gaze, speaking, turn_left, turn_right, thinking, silent_gaze` + 청자 반응 `nod, frown, glance, write` (반응은 얼굴/손 변화만 있는 별도 컷이어도 됨).
- 사절/수행원: 서 있는 알현 포즈 1~2종(국가별 문화 확정 금지, 복수 국가 대응 중립 의복).
- 컷신 스틸(교량 붕괴급) 사건별 후보 목록 + 서신/상자 클로즈업 컷인.
- 대화 하단 바용 초상 얼굴 크롭(이미 있는 카드 크롭으로도 가능).
- 프레임 세트(9-slice): 의견 카드, 발화 팝업, 결정 카드, 대사 바, 사건 개요 패널(사용 시).

1. (완료) 시안 확인 → 2. 본 문서로 상태/태그 최소안 확정 → 3. Codex 에셋 제작 → 4. Claude가 Ink+Unity 적용 → 5. HTML MVP와 대조 검증(도입/논쟁/선택 후 반응 복원 여부).

## 추가 (같은 날, 사용자 지시 반영)
- 열람 확인: 사용자가 물은 3장(무너진 교량 컷신 / 왕실 집무실 허브 / 왕국 지도·외교 관계 화면)은 위 §1·§4·§2에서 이미 검토했다. 컷신 = `Cutscene` 스틸 채택, 허브/지도 = 게임 구조 변경이라 사용자 결정 대기, 지도의 친밀도/관계 흐름 = 관계 수치라 미채택.
- **진행 길이 노출 금지**: 시안 우상단 "11 / 29 사건 진행"과 챕터/막 표기는 엔딩까지의 길이를 알려 준다. 건너뛰기/분기 때문에 실제 길이도 플레이마다 달라진다. Unity HUD에서 "사건 N/29", "ACT I~V", 기록의 "사건 N"을 제거했고 사건 제목(`# title`)만 표시한다. → Codex: 시안/UI 키트에서 진행 카운터·막 번호를 제외해 달라.
- **해석을 미리 설명하는 문구 금지**: 제목 화면의 "대신들은 저마다 다르게 읽는다"와 왕실 기록의 "무엇을 했는지만 남는다"를 제거했다(플레이어가 스스로 판단할 부분).
- 사건이 지금보다 훨씬 많아지고 건너뛰는/분기되는 장면이 늘어난다는 전제 → 사건 번호 기반 구간(Act 배경/음악)은 태그 기반(`# bg`, `# music`)으로 옮길 필요가 있다(다음 과제).
