# v6.6.0 — 개발용 완결 MVP 설계

사용자가 승인한 네 단계 확장의 첫 구현입니다. 블라인드용 v6.5.3에는 적용하지 않습니다.

## 발견한 기존 문제와 수정

- 1회차 finish()는 pressure/selfProtection/reciprocity 수치에 따라 결말을 골랐습니다. 과거에 교류를 끊었다가 마지막에 다시 열어도 selfProtection이 높으면 “문은 닫혔다”가 표시됐습니다. 마지막 선택 ID를 우선하는 7개 행동 문장으로 바꿨습니다.
- 1회차 회고 집계에서 마지막 선택 7종이 빠져 있었습니다. 교류 재개/유지, 기다림, 교류 축소의 해당 집합에 추가했습니다.
- 2회차 reopen_light_real은 상대가 움직이지 않은 상태에서 먼저 연락하는 행동인데 matched로 집계됐습니다. initiated로 변경했습니다.
- 회담 제안의 “상황을 명확히 하기 위해”, 교류 축소의 “소모를 줄이기 위해”, 관계 지속의 “불확실성을 감수하고” 등 선택자의 동기를 단정하는 로그를 행동 기록으로 바꿨습니다. 대신 캐릭터가 자기 관점에서 말하는 의견과 추측은 유지했습니다.

## 전체 흐름

1회차의 6사건과 2회차 진입 구조는 유지합니다. 1회차의 화면은 완결 게임의 최종 결말이 아닌 왕국 이야기의 중간 결말입니다.

2회차 기존 6장면 뒤에 아래를 붙입니다.

| 장면 | 역할 | 상호작용 |
|---|---|---|
| 7 남아 있는 날짜 | 결과 직면 | 있었던 일을 적기 / 오늘 일정 확인 |
| 8 창문을 여는 아침 | 일상 복귀 | 산책 / 미뤄둔 일 / 휴식 |
| 9 짧은 안부 | 재결정 | 지금 대화 / 짧게 답하고 기다림 / 일 마친 뒤 답 |
| 10 빈 왕좌 | 최종 장면 | 왕좌로 걸어가 앉기 → “내가 결정하지.” |

## 선택 회수

Scene 7의 설명과 도입은 Scene 6의 선택 7종을 읽습니다. 유지한 거리, 기다리는 연락, 필요한 용건만 남긴 연락, 다시 연 연락을 서로 다르게 보여줍니다. 다시 만남을 제안한 경우에는 답이 오지만 날짜는 정해지지 않습니다. 이는 관계 실패/성공 판정이 아닙니다.

Scene 9의 메시지는 이전 관계의 상대가 아닌 다른 사람에게서 옵니다. 먼저 관계를 열거나 끊은 행동이 “보상으로 연락을 받는 정답”이 되는 것을 피하면서, 새 상황에서 다시 선택하게 합니다.

최종 화면은 이전 관계의 Scene 6 행동과 새 대화의 Scene 9 행동을 각각 표시합니다. 새 대화가 이전 관계 이력을 덮어쓰지 않습니다. 일상 선택은 관계 행동 집계에 섞지 않고 별도 횟수로 표시합니다. 왕좌 행동도 총 결정 수에는 남지만 관계 행동 분류에는 포함되지 않습니다.

## 연출과 범위

- 새 인물/내면 기능/감정 수치/엔딩 등급은 추가하지 않습니다.
- 2회차의 밝은 화면, 의견 카드, 선택지와 기록 위치를 유지합니다.
- 일상 장면에 창문/탁자, 마지막 장면에 빈 의자 형태의 자체 SVG를 추가했습니다.
- 빈 왕좌 장면은 의견 카드와 일반 결정 안내를 숨겨 대화 루프를 짧게 마무리합니다.
- 왕의 직접 발화는 마지막 장면 한 번입니다. 기존 “왕은 말하지 않는다” 원칙의 사용자 승인된 엔딩 예외입니다.
- KING WAS YOU나 심리적 기능의 해설 문장은 추가하지 않았습니다. 최종 타이틀은 KING WAS ME입니다.
- 현 단계는 단일 완결 경로 검증입니다. 관계 결과별 다중 엔딩과 Unity 연출은 미구현입니다.

## Claude 검토 요청

1. Scene 7의 관찰 가능한 상대 행동이 이전 선택과 자연스럽게 이어지는지.
2. 기존 동기 단정 문구의 정리가 충분한지. 캐릭터의 추측과 공식 기록을 구분해서 검토.
3. Scene 9의 다른 사람에게서 오는 안부가 정서적 연결을 끊지 않는지.
4. 빈 왕좌까지의 분량과 마지막 발화가 충분히 쌓이는지. 자동 검증으로 판단할 수 없는 영역입니다.
5. 직접 브라우저에서 원본을 열고 화면/스크롤/모바일 배치/최종 장면을 확인. Codex 브라우저는 로컬 HTML 접근 정책에 막혔습니다.
