## 1. 현재 상태 한 문단 요약

Unity 드래프트는 **연출 골격은 상당히 완성됐지만 그 안에서 재생될 이야기는 아직 골격**인 상태다. 좌석 뷰·발언 팝업·의견 카드·왕의 정적·태그 기반 단계 러너·에셋 카탈로그·오디오는 실제로 동작하고, 빌드를 막던 에디터 전용 의존성도 해소됐다(이전 감사 대비 실질 개선). 그러나 기본 경로를 끝까지 재생하면 **총 28화면 5,237자**이며, 그중 절반 가까이가 MVP 원문을 이식한 사건 4·6·8 세 개에 몰려 있고 나머지 26개 사건은 평균 3줄이다. 더 심각한 것은 **엔딩이다**: 게임 전체의 장치인 `KING WAS YOU` → 빈 왕좌 → `"내가 결정하지."`가 전용 연출 없이 평소 회의실 좌석 뷰 위에 좌상단 서술 한 줄로 흘러가고, `"암전."`·`"카메라가 왕의 자리로 이동한다"` 같은 **무대 지시와 설계 메모가 플레이어에게 그대로 출력된다**. 동시에 이미지 에셋은 64장 중 55장(133MB)이 런타임에 연결되지 않았고, 코드에 구현된 태그 9종(`cutscene`/`pause`/`met`/`bg`/`music`/`react`/`cutin`/`chapter`/`timer`) 중 Ink가 실제로 쓰는 것은 0개다. 즉 **표현 수단과 에셋이 콘텐츠보다 앞서 있으며, 이는 `DESIGN_INTENT.md` §D-5·§D-6이 이탈 신호로 명시한 상태와 정확히 일치한다.**

## 13. 확인하지 못한 사항과 검토의 한계

**실행하지 못한 검증**
- **Standalone 빌드 실행** — 코드상 장애물은 사라졌으나(§3-5) 실제 빌드를 돌리지 않았다. 빌드는 에디터 상태를 바꿀 수 있어 감사 범위에서 제외했다. **빌드 가능 여부는 미검증.**
- **945x435·21:9 등 다른 해상도** — Game 뷰 크기 변경이 에디터 설정을 저장할 수 있어 제외. 1280x720만 실측.
- **5명 이상 좌석 레이아웃** — 로스터에 5번째 상시 대신이 없어 미검증.
- **마우스 오버 확대·실제 마우스 조작** — `eval_file`로 `BubbleClick`을 직접 호출했을 뿐, 실제 포인터 이벤트는 미검증.
- **오디오 실청** — 들을 수 없다. 카탈로그 연결과 `AudioSource` 재생 여부만 확인.
- **메모리·성능** — 미측정.
- **방문 루트(royal_visit) 전체 플레이** — inkjs 스윕에는 포함됐으나 Unity 화면으로는 미확인.
- **HTML MVP(KINGDOM_SLICE) 실제 플레이** — 브라우저로 돌리지 않았다. "MVP 대비" 판단은 소스 정독 기준.

**뒷받침이 약한 주장**
- "출시까지 1/4 지점"(§2)은 **추정치**다. 남은 콘텐츠 분량을 사건당 15~20줄로 가정해 계산했으며 검증된 수치가 아니다.
- 리안 이름 어말 충돌(§7)은 한국어 화자로서의 **주관적 판단**이다.
- "가장 잘 만들어진 연출은 왕의 정적"(§7)은 캡처 기반 인상이며 실제 플레이 감각은 사용자만 판단할 수 있다.
- §2의 퍼센트 전반은 축별 가중치를 내가 임의로 정한 것이다.

**구조적 한계**
